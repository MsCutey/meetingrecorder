# AI 会议纪要调研与 macOS 会后处理 MVP

调研日期：2026-10-23。目标分支：`codex/macos-post-meeting-notes`。本分支供人工检查，不在本轮合并。

本文记录产品调研、技术选择、实现范围及验收方法。本轮已实现官方 ChatGPT 订阅登录与文字总结。真实用户 OAuth 授权、云端 API 连通性、账号用量、中文转写准确率和纪要质量仍待使用有效账户验证，不能把文档核对或模拟测试视为真实服务验收。

## 1. 结论与首轮范围

先尝试 **macOS 会后云端识别与总结**。复用项目已有录制与历史文件入口，处理已经保存的录音或视频：本机抽取音轨，分段调用语音转写 API，再把文字交给摘要服务生成中文纪要。

转写与总结分开配置：转写使用独立 API，预设为 OpenAI；总结可以使用 ChatGPT 订阅，或 DeepSeek、OpenAI API 及兼容服务。新用户默认选择 ChatGPT 订阅总结，升级前已保存的 API 配置继续保持 API 方式。会中实时识别尚未实现，会议录制结束也不会自动上传。

产品重点是概要、讨论要点、明确决策、待办事项和未决问题，以及原文回溯、编辑、导出和失败恢复。负责人或期限未明确时应保留“未明确”，建议不能被写成已达成的决策。

## 2. 现有产品的共同做法

以下是官方资料可确认的功能，不代表完成了这些商业产品的实际效果评测。

| 产品 | 官方能力 | 本项目借鉴点 |
| --- | --- | --- |
| Otter | 会中展示转写草稿，会后继续处理最终转写与摘要，也支持导入音视频后处理。 | 将转写与摘要拆为独立阶段，明确等待状态与结果状态。[官方处理流程](https://help.otter.ai/hc/en-us/articles/360048322493-Transcription-processing-time-FAQ) |
| Fireflies | 提供实时转写和待办；会后摘要包含概要、结构化笔记、带时间戳的章节和行动项，可按模板重新生成。 | 标准纪要结构、原文关联、重新生成。[会后摘要](https://guide.fireflies.ai/articles/9547055509-fireflies-ai-meeting-summaries)、[实时能力](https://fireflies.ai/product/real-time) |
| Granola | 会后结合转写、用户手记及日历上下文生成笔记，可查看笔记要点的来源。 | 保留原文依据，给人工编辑与补充上下文留入口。[官方说明](https://docs.granola.ai/help-center/taking-notes/ai-enhanced-notes) |
| 飞书妙记 / 智能纪要 | 同时提供会中实时总结与会后回顾；录制后的妙记可包含智能纪要，结合章节和待办整理内容。 | 将长会议整理成可浏览的要点与任务。[产品介绍](https://www.feishu.cn/product/ai-meeting-summary)、[智能纪要开启方式](https://www.feishu.cn/hc/zh-CN/articles/244959839578) |
| 腾讯会议 | 会后可开启智能录制，生成基本信息、摘要、纪要与待办；支持纪要关联原文、编辑、模板重生成和 Markdown 复制。 | 可校对、可修订、可导出，避免只生成不可追溯的一段摘要。[新版智能录制](https://meeting.tencent.com/support/topic/2228/index.html) |

这些产品共同强调“转写之后的可用结果”。本轮优先完成稳定的会后处理链路，并不尝试一次覆盖会议机器人、跨会议搜索、说话人识别和协作任务分发。

## 3. 实时与会后处理的工程比较

以下难度比较是结合本项目已有录制能力做出的工程判断，不是厂商公布的开发工时。

| 方面 | 会后处理 | 实时处理 |
| --- | --- | --- |
| 输入与传输 | 完整文件，可在本机抽取音轨、分段、失败重试。 | 持续采集与分帧，需要流式传输、缓冲、网络抖动处理和连接恢复。 |
| 转写状态 | 每段结束后保存相对稳定的结果。 | 临时结果可能改写，要维护非最终文本和最终文本。 |
| 总结上下文 | 可以看到完整会议，区分早期建议与后期决定。 | 要不断增量归纳、去重，并更正被后续讨论推翻的结论。 |
| 故障恢复 | 原录音和已完成分段可作为恢复依据。 | 需要补传音频、处理丢帧与重复结果，并维持连续时间轴。 |
| 验收 | 同一固定录音可以重复比较。 | 还要验证延迟、断网、语速变化、长连接和会中 UI 更新。 |
| 首轮适配度 | 高：现有本地文件可直接作为输入。 | 后续迭代：需要修改正在运行的录制链路。 |

实时转写的额外状态确实存在。例如腾讯云实时 ASR 官方接口要求控制音频发送速率和包间隔，区分可变化的非稳态结果与稳态结果，并规定断线后重新建立识别标识。[实时 ASR 文档](https://cloud.tencent.com/document/product/1093/48982)

“流式显示一个已录完文件的转写”与“边录边识别”也不同；前者仍可采用文件转写流程。本轮先采用完成文件的处理路径。[OpenAI 转写工作流](https://developers.openai.com/api/docs/guides/transcription)

## 4. 云服务配置与接口边界

| 角色 | 默认基础地址 | 默认模型 | 调用接口 | 凭据与输入 |
| --- | --- | --- | --- | --- |
| 语音转写 | `https://api.openai.com/v1` | `gpt-transcribe` | `POST /audio/transcriptions`，multipart 文件上传，读取 JSON 中的 `text`。 | 转写服务的 API Key；只发送抽取后的 M4A 音轨。 |
| 纪要总结（新用户默认） | `https://api.openai.com/v1`，固定官方入口 | 从已登录账号的模型列表选择 | `POST /responses`，`store:false`、`stream:true`，解析 SSE 的完整结果。 | 本应用通过 ChatGPT 官方登录取得的授权；只发送完整转写文字。 |
| 纪要总结（API Key 方式） | DeepSeek 预设 `https://api.deepseek.com` | `deepseek-flash` | `POST /chat/completions`，发送文字消息，读取最终文本。 | 摘要服务的 API Key；发送转写或分段归纳文字。 |

API 配置栏填写服务基础地址，不能填写完整的 `/audio/transcriptions` 或 `/chat/completions` 路径。应用会添加接口路径。自定义转写服务必须实际支持所选模型、M4A 输入和 JSON `text` 输出；自定义总结服务必须兼容 Chat Completions。ChatGPT 订阅方式使用独立适配层，不接受自定义基础地址或通用 API Key。

OpenAI 官方文件转写文档当前推荐 `gpt-transcribe`，单个文件上限 25 MB。应用为每个导出的分段设置低于服务上限的体积保护。该模型的语言提示参数使用 `languages`；不能直接照搬旧模型的 `language` 参数。此前 Whisper / GPT-4o 转写系列已列入弃用计划，因此新接入不以它们作为默认模型。[文件转写指南](https://developers.openai.com/api/docs/guides/speech-to-text)

DeepSeek 官方首页当前列出 OpenAI 兼容基础地址 `https://api.deepseek.com` 与模型 `deepseek-flash`；Chat Completions 文档定义了文字对话的请求与响应。本次查阅的官方 API 文档未提供可用于会议音频的语音转写接口，因此 DeepSeek 在本方案中只负责文字纪要，不作为音频转写服务。[DeepSeek 接入说明](https://api-docs.deepseek.com/)、[Chat Completions 接口](https://api-docs.deepseek.com/api/create-chat-completion/)

API Key 按各厂商 API 用量计费。使用 OpenAI API Key 不会自动消耗 ChatGPT 订阅内的额度。[OpenAI 认证与计费说明](https://learn.chatgpt.com/docs/auth)

## 5. ChatGPT 订阅：本轮实现与边界

截至调研日，OpenAI 已提供正式的 **Sign in with ChatGPT（SIWC）** 路径。符合条件的 Plus / Pro 用户可以授权开源或本地应用使用套餐额度，官方示例包含桌面文字处理应用。收费或远程托管应用的接入要求另行申请，不能把本地开源场景的规则直接套用到所有商业服务。[官方 Cookbook](https://developers.openai.com/cookbook/articles/sign-in-with-chatgpt)、[适用范围](https://developers.openai.com/siwc/token-sharing-open-source)

当前 SIWC 限制明确：**不支持音频/视频输入、Files 上传 API 和转写 API**。本应用将它用于“已有转写文字 → 纪要”；音频识别仍使用独立 API，不会使用 ChatGPT 订阅额度。[官方限制](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)

操作入口是 **“AI 服务设置 → 纪要总结 → ChatGPT 订阅 → 使用 ChatGPT 登录”**。系统浏览器打开官方授权页面，返回应用后展示账号和可用模型。身份登录与使用套餐额度分别检查；只登录但未授权套餐时，界面提供“启用套餐额度”。没有可用模型、账号不符合条件或达到额度上限时会提示原因，不自动回退到收费 API。

本轮代码实现包括：

1. OAuth PKCE、回环地址回调、`state` / OIDC `nonce` / JWT 签名校验；使用本安装的稳定 host ID 和本应用注册信息。已取得的 client ID 在授权交换失败时保留，重试可恢复注册，不将未验证的账号标为已登录。[注册与登录](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)
2. 独立 Keychain 凭据存储，与转写和总结 API Key 分开。重启后恢复本应用的账号；请求前按需刷新凭据并保存轮换结果。退出时尝试远端撤销并清空本机 access / refresh / ID token，保留账号对应的非 token 注册信息供再次登录；远端撤销未确认时会明确提示。[账号与会话](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions)
3. 按已登录账号查询公开模型目录，只显示可选择的模型；通过公开 `/v1/responses` 发送 `store:false`、`stream:true` 请求并解析 SSE。仅接收完整完成事件，不保存半截回复、拒绝响应或无效来源标记。当前订阅路径发送完整转写，超过上下文时要求拆分，不截断原文。[模型与推理](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)
4. 界面和处理确认窗口明确显示使用 ChatGPT 套餐及当前账号。接入不会新增额度，而是共享既有 Codex / ChatGPT Work 限额；具体账号资格、模型和用量以官方返回及 ChatGPT 设置为准。[用户侧额度说明](https://learn.chatgpt.com/docs/sign-in-with-chatgpt)

这条路径不是任意通用 Key 或第三方网关的替代品。应用不读取其他应用的登录 token，不调用非官方网页后端，也不通过普通 Chat Completions 客户端传递订阅凭据。真实账号授权与套餐推理尚未执行，因此“已实现”指源码和本地模拟验证，尚不能宣称生产服务已验收通过。

“复制给 ChatGPT / 粘贴纪要”仍保留为可选手动操作；复制仅写入系统剪贴板，由用户自行发送。应用内订阅登录与此手动入口是两条独立路径。

## 6. 首轮实现流程与数据保存

```text
历史录制 / 导入音视频
    → 读取本地音轨与时长
    → 每段最多 5 分钟，在本机抽取为 M4A
    → 云端语音转写，每完成一段保存检查点
    → ChatGPT 订阅文字总结，或独立 API 总结
    → 人工编辑 / Markdown 导出（也保留手动复制给 ChatGPT）
```

- 输入入口支持 MP4、M4A、MOV、MP3、WAV、AIFF 等系统可解码的音视频。扩展名可选择不代表任意编解码器都可处理；文件必须包含可读取的音轨。
- 处理由用户点击“仅转写 / 继续”或“生成纪要”发起，并展示本次内容将发送到的服务。录制、停止录制和打开历史列表不自动上传。
- 原视频画面不上传；云端转写只接收本机导出的音轨分段。摘要服务接收文字，二者可以是不同厂商。
- 请求前验证目标位置可原子保存，避免明知目录不可写仍先上传；之后每段成功保存检查点。例如 `meeting.mp4` 对应 `meeting.mp4.notes.json`，`meeting.m4a` 对应 `meeting.m4a.notes.json`。预检只能确认当时可写，不能保证处理期间磁盘空间不会被其他进程耗尽。
- 附加文件保存源文件信息、分段原文、完成状态、服务/模型配置和纪要，不包含 API Key 或订阅 token。应用通过源文件大小、修改时间等信息检查能否复用转写，并在上传前再次检查；这不是文件内容哈希验证。
- 有音轨的视频若开头或尾部某个分段完全没有音轨，该段记录为空转写并跳过上传，后续分段仍可继续；整场无音轨的文件仍会拒绝。
- 界面展示准备音频、分段转写和总结进度，并允许取消。已完成分段保留；再次处理可继续。取消不能撤回已经发送的服务请求，也不能保证撤销已发生的计费。
- 转写完整后，重新生成或重试纪要直接使用已保存文字，不重新上传音频。总结失败或取消时保留已有转写和旧纪要。
- 修改录音或切换转写服务后需要显式重新转写；重新转写先备份旧附加文件，避免把不同来源的文本混在一起。
- API Key 存入 macOS Keychain，按“服务基础地址 + 转写/总结角色”区分；普通偏好设置只保存非敏感配置。切换服务地址时，不把上一服务的 Key 带到新地址；未保存的 Key 草稿随地址保留，选择其他录音不覆盖草稿。
- 纪要草稿可编辑并保存；Markdown 导出包括纪要和带分段标签的转写。保存时检测外部修改，避免覆盖其他操作的结果；成功导出当前草稿后可以离开窗口，再次编辑则重新触发未保存保护。导出不能覆盖原录音或 `.notes.json`。
- API 总结对长文本分段归纳再合并；订阅总结发送完整转写，超过模型上下文时明确报错。两条路径都不静默截掉后半场。网络响应按流限制体积，超限即停止处理。

## 7. 已知边界

- `[S1]` 等标签定位的是最多 5 分钟的粗粒度音频范围，不是逐句或逐词时间戳，也没有自动识别说话人。
- 固定分段边界可能切开词语或句子，影响边界附近的转写。首轮没有基于静音的切分或重叠片段去重，需在真实录音上检查影响。
- 最长支持 8 小时录制；这只是输入上限，不代表已完成 8 小时真实会议的时长、资源占用或质量验收。
- 转写错误会传播到摘要，分段归纳也可能遗漏细节。来源标签和提示词可以辅助核对，但不等于事实正确性的保证。
- 尚不覆盖会中实时字幕/实时总结、说话人分离、跨会议检索、自动待办分发或云端自动同步。正式 SIWC 登录和文字总结已实现，但真实账号 OAuth、云端模型及图形界面仍待验收。

## 8. 可执行验收步骤

以下均为验收计划。**真实 API 用例当前待验证**；执行后应记录日期、系统版本、服务/模型、脱敏错误信息和实际结果，不记录 API Key。使用可以发送给所选服务的测试素材，留意 API 用量。

### 8.1 编译与本地测试

在仓库根目录执行：

```sh
bash scripts/build-macos.sh
```

脚本运行测试并构建、签名和打包 Apple Silicon 应用，也处理部分 Command Line Tools 版本所需的 Testing 宏插件。音轨测试访问本机媒体编码服务；在限制 IOSurface 的执行沙箱里需要允许该本地服务。记录实际结果。自动测试即使通过，也只证明其覆盖的本地逻辑或模拟接口行为；不能据此填写“OpenAI / DeepSeek 真实调用已通过”。既有录制功能的验证记录见 `docs/ACCEPTANCE-macOS.md`，它不替代本次 AI 功能验收。

### 8.2 独立 API 的完整链路（待真实 API 验证）

1. 准备约 6–10 分钟中文音频，确保跨过 5 分钟边界。内容包含明确决策、只有建议尚未通过的议题、明确负责人及期限的待办，以及未指定负责人的任务；在后半段加入一个独立的重要结论。
2. 从历史录制打开“会后纪要”，或通过“选择文件”导入素材。展开“AI 服务设置”，在“纪要总结”选择“API Key”，分别填写转写和总结的基础地址、模型与有效 Key，保存配置。
3. 点击“生成纪要”，核对确认窗口的两个目的地，然后开始。预期看到多个分段进度，并在源目录出现 `.notes.json`。
4. 检查“转写原文”：前后两段都有内容，`[S编号]` 时间范围连续，未把前段重复写到后段，也未遗漏会议后半段。
5. 检查“纪要草稿”：包含概要、讨论要点、明确决策、待办和未决问题；负责人/期限依据原文；建议没有变成决策；来源标签实际存在且能找到支持内容。
6. 对照录音核查姓名、产品名、数字与片段边界。记录错误样例；不能只以返回 HTTP 成功判定效果合格。

### 8.3 ChatGPT 订阅登录与应用内总结（待真实账号验证）

1. 打开“AI 服务设置 → 纪要总结 → ChatGPT 订阅”，点击“使用 ChatGPT 登录”。新用户应默认选择订阅；升级用户应保留之前的 API 方式，切换由用户明确选择。
2. 在系统浏览器完成官方账号登录和套餐使用授权，检查返回应用后显示的账号。若未授予套餐权限，使用“启用套餐额度”；取消登录或回调失败时，不应替换既有已登录账号。
3. 检查账号实际返回的模型列表，选择其中一个模型。没有可用模型、账号不符合条件或额度不足时应明确提示；不能偷偷改用 API Key 服务。
4. 为音频转写单独配置有效 API Key，或选用已有完整转写。点击“生成纪要”，确认窗口应分别说明音轨的 API 地址与文字总结使用的 ChatGPT 账号和套餐；已有完整转写时不应再次上传音频。
5. 对照原文检查完整纪要与来源。拒绝、未完成 SSE、连接中断或上下文过长时应保留旧稿，不能保存半截结果。通过官方用量页面核对实际套餐消耗，不能用模拟请求证明账号计费行为。
6. 重启应用检查本应用登录恢复；点击“刷新模型”或再次总结，核查凭据刷新和当前模型可用性。退出应清空本机 token、保留非 token 注册信息；再次登录复用本应用注册，远端撤销失败时应看到明确提示。

### 8.4 取消与转写恢复（待真实 API 验证）

1. 对新的多分段素材选择“仅转写 / 继续”，至少等待第一个分段保存，然后点击“取消处理”。
2. 关闭并重新打开纪要窗口，确认已完成分段仍存在，未完成状态明确。
3. 使用相同录音和转写配置继续。预期从未完成的分段开始，不重复识别已保存分段；已经发出但尚未落盘的请求可能在恢复时重做。
4. 在可丢弃素材副本上更改源文件，或改变转写模型，再尝试继续。预期提示重新转写；选择“重新转写（备份旧纪要）”后，旧文件应有备份。

### 8.5 总结失败与重试不重传音频（待真实 API 验证）

1. 先完成“仅转写 / 继续”。使用 API Key 总结方式，把总结 Key 临时改为无效值，点击“生成纪要”，检查可理解的失败提示和仍然完整的转写。
2. 恢复正确的总结 Key 后重试。确认本次提示只发送转写文字；借助服务用量记录或不记录正文/凭据的请求计数，核实没有新的音频转写请求。
3. 已有纪要时再次制造总结失败或取消，确认旧纪要没有被清空或部分覆盖。

### 8.6 编辑、导出与手动 ChatGPT 路径

1. 编辑一条纪要，点击“保存修改”，重新打开检查保存结果；导出 Markdown，检查中文、纪要、全部转写和粗粒度时间范围说明。
2. 在可丢弃的副本上模拟外部修改 `.notes.json`，再保存编辑，确认不会覆盖外部结果。将当前稿导出到新 Markdown 文件，成功后应能关闭或切换录音；再次编辑后应恢复未保存保护。
3. 完成转写后点击“复制给 ChatGPT”，在本地文本编辑器粘贴，确认包含原文与中文提示词，界面提示“尚未发送内容”。
4. 可选的手动路径由用户自行在 ChatGPT 粘贴并发送，再把生成结果带回纪要草稿保存；它与 8.3 的应用内 SIWC 登录分别验收。

### 8.7 服务隔离和异常输入

1. 保存两个角色的配置与 Key，关闭并重开应用，检查原地址的 Key 可正常读取。编辑未保存的 Key 后切换录音，草稿应保留；改成另一服务地址时不沿用旧地址的 Key，切回应恢复该地址草稿。显式“读取已保存的 Key”才重新读取记录，读取失败时不能误删原凭据。不要在测试日志输出 Key。
2. 验证录制、停止录制、浏览历史和仅打开纪要窗口不会自动发送云请求。
3. 分别导入无音轨视频、损坏媒体、静音录音和超过 8 小时的测试文件。预期拒绝不可处理输入或说明没有可总结文字，不覆盖原始媒体。视频只有尾部某段无音轨时，应跳过该段上传并完成其余转写。静音是否被模型误识别仍需真实 API 检查。
4. 对网络失败、鉴权失败、限流以及源目录不可写检查错误提示。目录从开始就不可写时，应在发起转写或总结请求前失败；保留能恢复的本地结果，并记录未通过项。
