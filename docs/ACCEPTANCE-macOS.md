# macOS 1.2.0 beta 验证记录

验证日期：2026-10-22。开发机：Apple Silicon Mac mini，macOS 27.0 (26A428)，Command Line Tools / Swift 6.4。

## 已完成

- Apple Silicon 和 Intel 两种架构均通过 release 编译、应用打包和 ad-hoc 签名完整性验证。
- 4 项自动测试通过：暂停时间统一扣除（含迟到采样）、非法/早到时间戳过滤、视频比例与偶数尺寸、已有文件防覆盖。
- 开发进程真实整屏试录生成 1920×1080 MP4，1 条视频轨、1 条音轨，可解码画面；录制 6 秒内容，中间暂停 2 秒，输出约 6.31 秒。
- 开发进程真实系统声音试录生成 M4A，0 条视频轨、1 条音轨；中间暂停 2 秒，输出约 6.10 秒。独立测试应用播放 440 Hz 测试音，源音频峰值约 0.0732，成品解码峰值约 0.0754，验证了非静音内容。
- 固定安装的最终应用已在自身屏幕权限下，通过 LaunchServices 正常启动并完成真实整屏试录：1920×1080，1 条视频轨、1 条混音音轨，约 6.22 秒，成品音频峰值约 0.0808，画面可解码。已核对安装程序与已上传 ZIP 中的可执行文件 SHA-256 一致。
- 最终应用后台启动、目标测试窗口保持活动时，窗口 MP4 验证通过：320×132、约 6.13 秒，1 条可解码视频轨和 1 条非静音音轨，音频峰值约 0.0744。中间暂停 2 秒不进入成品。
- GitHub Actions 的 macOS 两架构构建成功，运行链接：[验证运行](https://github.com/MsCutey/meetingrecorder/actions/runs/39799612737)。
- 测试中临时使用内置扬声器，结束后恢复原来的显示器音频输出。
- 所有屏幕截图、试录文件及硬件诊断留在本地被忽略的 `artifacts/`，不随源码或发布包上传。

## 权限问题及窗口限制

- 开发中 ad-hoc 签名变化造成 TCC 保存的旧 cdhash 与当前程序不匹配，日志确认过该情况。仅重置本应用的旧屏幕授权、移除构建目录中的重复应用注册并固定安装后，已恢复上方“录屏与系统录音”权限，正常应用试录通过。下方“仅系统录音”的授权不能代替上方权限。最终应用没有再重建或重新签名。
- 本机台前调度会将非当前窗口缩小并挂起，ScreenCaptureKit 返回 `SCFrameStatus.suspended`，此时没有完整视频帧；启动时按缩略窗口尺寸配置也可能导致低分辨率或不可解码视频。仅保持目标窗口活动的测试通过。使用窗口模式时将目标窗口保持在当前台前组，避免最小化或收为台前调度缩略图；无法保证时请使用整屏模式。该限制尚未在产品内自动处理。

## 尚未通过或没有硬件条件的项目

- 本机无输入设备，未实录验证外接麦克风、双路混音内容或麦克风静音切换；相关路径不能视为已完成硬件验收。
- Intel 包仅交叉编译，没有 Intel 实机验收。最低版本 macOS 15 没有实机回归。
- 未验证长时会议、设备热插拔、磁盘满、强制退出后的恢复成功率和休眠/锁屏行为。
- 桌面 UI 自动化服务在首次界面检查时崩溃，恢复后完成了系统权限状态检查，但未完成产品所有控件的自动化界面验收。

本次按预发布测试版交付，保留上述边界。发布包不具有 Developer ID 或公证签名，不应标为正式稳定版。

## 后续人工验收

1. 将最终 `.app` 固定放在“应用程序”，完成屏幕与系统音频授权，退出并重新打开。
2. 分别选择显示器和浏览器窗口，播放测试音并录制，检查画面、声音和暂停后的时长。
3. 外接麦克风，检查单麦克风、双路声音以及开始静音、录制中静音和恢复。
4. 验证菜单栏控制、关闭后重开窗口、退出保存、历史播放/定位/删除。
5. 用至少 30 分钟的录制检查音画同步、内存和磁盘使用；在可丢弃试录中验证异常恢复。

## Build 3：Computer Use 兼容性验证（2026-10-24）

- 将问题收敛为应用特定的辅助功能树触发：同一会话可读取系统计算器及普通 SwiftUI 窗口；`GroupBox`、分段选择器、下拉菜单、可选文字、空状态视图单独使用均通过。`ScrollView` 内的原生 `GroupBox` 组合稳定触发 Computer Use 26.1015 的 `UIElementTreeTransformation.transform` → `Array.remove(at:)` 崩溃。仅把外层 `HSplitView` 换成 `HStack` 无效；替换滚动区内的分组容器后通过。
- 主窗口的四个分组改为普通标题与容器绘制边框，保留全部可访问控件、绑定、按钮行为及可拖动 `HSplitView`。未修改、替换或重签名官方 Computer Use 组件。
- 84 项自动测试通过（73 + 11），Apple Silicon Release Build 3 打包与 ad-hoc 签名验证通过，已安装到 `/Applications/MeetingRecorder.app`。
- 真实 Computer Use 操作已通过：完整主窗口读取、打开会后纪要、经系统文件面板导入隔离合成 WAV、读取已有示例纪要、清空编辑器后继续输入、保存修改。另行读取测试 `.notes.json` 验证 `UI-BUILD3-20261024` 标记确实落盘。
- 系统 Markdown 保存面板的保存按钮处于不可用状态；取消后 Computer Use 报 `timeoutReached`，未完成导出界面验收。这与前述 `SIGTRAP` 崩溃不同；进程采样显示应用主线程已回到正常事件循环，尚未确定是系统面板还是控制工具的窗口状态问题。
- 上述素材均为本机生成并复制到独立测试目录，不是真实会议材料，未发起云端转写、套餐授权或付费请求。真实 OAuth、识别效果和录制硬件验收范围仍以各自记录为准。

## Build 4：纪要文件面板操作验证（2026-10-24）

- 在 Build 3 重测中，文件选择面板也出现已选中 WAV 但确认按钮不可用的状态。将导入、导出的 `runModal()` 改为绑定当前纪要窗口的 `beginSheetModal(for:)`；窗口由 SwiftUI 内的轻量 NSView 捕获。面板打开期间保留实例并保护关闭/退出，完成或取消时清理状态、关闭面板、恢复纪要窗口焦点。
- 保持原来的音频类型、Markdown `UTType` 和落盘方法不变，因此没有把动态 Markdown 类型误认作已确认根因。
- 面板所属窗口由每个纪要视图独立持有弱引用；面板期间阻止其他窗口切换录音、修改纪要或启动 AI 处理，避免导出文件名与内容不匹配。多窗口并发操作尚未做真实界面验收。
- 实际 Computer Use 对照验证通过：选择相同隔离 WAV 并确认导入；编辑并保存 `UI-BUILD4-FINAL-20261024` 标记；导出面板 Save 按钮可用；设置 `ui-build4-final-verified.md` 后成功导出并立即返回纪要窗口；再次打开导出面板并取消；正常关闭纪要窗口返回主窗口。上述路径未再次出现 `timeoutReached`。
- 面板刚打开或刚完成路径跳转时，控制工具有时短暂报告确认按钮 disabled；完整读取后按钮恢复可用并能成功确认。未将该读数断言为 SwiftUI 禁用状态传播或 Markdown 类型错误。
- 另行读取导出的 UTF-8 Markdown，确认保存的纪要全文、全部转写片段、中文及 `[S1]` 来源标记均存在。原测试 `.notes.json` 与音频保留。
- 84 项自动测试再次全部通过，Apple Silicon Release Build 4 签名和打包通过，并已安装到 `/Applications/MeetingRecorder.app`。这补齐了 Build 3 的导出界面待验收项；真实云端服务和硬件录制的未验证范围不变。

## Build 5：窗口录制尺寸与失败恢复（2026-10-25）

- 用户成品为 256×276、2.68 秒；两份失败 partial 均只有音轨。系统日志记录选源为128×138 points、比例2，随后窗口挂起。旧实现使用缩略呈现尺寸初始化编码器，且直到停止才报告没有画面。
- 窗口入口改用系统单窗口选择器，保留选择时的完整几何与授权；显示器及开发试录的窗口ID在倒计时后重新查询。采集使用 `.best` 并忽略窗口阴影。显示实际输出像素，不用人为放大缩略图掩盖缺失画面。
- 开始需要流启动完成及首个有效媒体写入；视频模式首帧前不写入音频。10 秒超时、取消、晚到回调采用单次终态；空的启动失败文件清理，已有内容保留。准备期间可取消，状态提示可关闭，退出准备时先取消。捕获到 suspended 会明确提示画面停止更新。
- 系统选窗对照：选中窗口1293×922 points、比例2，前台38个完整帧；转入台前调度2.619秒后 suspended，20秒只保存2张诊断帧。另测 `.ignoreGlobalClipSingleWindow=true`，6.34秒无完整帧。两者均不能解决该系统状态下持续录制，不能把系统选窗本身称为后台修复。
- 用户同意临时关闭台前调度验证兼容方式。实际安装版自带试录捕获公开时钟浏览器窗口（无音频），后台录制与暂停恢复通过：1512×1080、6.055秒。解码1秒/5秒帧，时钟20:05:25→20:05:31，符合扣除2秒暂停；地址栏、日期和页面小字可读，原来的大片下方黑边消失。同期前台应用只读检测为 ChatGPT。
- 正常界面流程由用户确认系统选窗，Computer Use 核对“正在录制”与输出像素后点击“停止并保存”。成品 `Meeting_2026-10-25_20-12-15.mp4` 为1512×1080、16.8517秒，433帧全部解码至结尾；时钟20:12:15→20:12:32。取消选窗立即回到就绪，关闭提示按钮确实清除消息。
- 恢复台前调度后重新测试已知无画面场景：10秒启动超时，进程正常结束，自测目录只有结果JSON，没有残留partial/MP4。该测试的 `success:false` 表示预期的启动拒绝，而非误报录制成功。用户原有两份失败文件与低清视频保留。验证后已通过系统界面确认台前调度开启，系统声音选项恢复开启。
- 89项自动测试通过（73 RecorderSupport + 16 App）；其中新增5项覆盖首帧/流回调顺序、取消/超时晚回调与音频不能触发视频启动。测试不替代真实系统录制验收。证据留在被忽略的 `artifacts/window-recording-2026-10-25/`，不上传用户录制或截图。
